## E1 — rarity weighted gate vs raw overlap size sweep
- Date: 2026-10-10
- Project: local/sandbox-keyword-gate-rarity
- Tags: [tooling][process][testing][search]
- What: Size-sweep of the brain commit gate's keyword-overlap check against 76 real open-question headings, using unrelated Python stdlib source as the "diff" at 50/200/800/3200 words. The live-style gate (substring match, floor 2, bar scaled to heading size) fires on 1% / 7% / 36% / 93% of unrelated diffs by size. A rarity-weighted gate (idf mass from held-out background, bar = half the heading's idf mass) fires on 0% / 0% / 1% / 5% with recall 1.00 on planted on-topic edits.
- Why built: The kernel keyword-match-over-prose says raw overlap rewards long inputs, so a higher threshold fires on bigger work not more relevant work, and that rarity weighting is the fix. brain/E46 and brain/E59 record the symptom (generic nouns tripping the gate, a reflexive ack). Nobody had measured the size curve or asked where the fix stops working.
- Design: Keywords extracted exactly as the live gate does (type field dropped, stop-list, 5+ letter tokens, copied read-only from the CLI source). Unrelated "diffs" are consecutive word windows of stdlib source (even windows calibrate idf, odd windows evaluate). On-topic edits are planted by appending half of a heading's keywords to an unrelated window (highest-idf half, and a break variant using the lowest-idf half). Gates compared: live, fixed raw 2, fixed raw 4, uniform half-of-keywords, idf-mass half, headings-only idf, idf calibrated on the wrong domain, and a windowed (co-located) idf-mass. A second corpus of ideas prose is a topical control.
- Got right: Raw overlap does track diff size (raw>=2 on code: 0.02/0.16/0.65/0.99) and raising the bar trades relevance for size: raw>=4 on code keeps FP low (0.00/0.00/0.01/0.12) but recall collapses to 0.31-0.42, and on topical prose its recall rises 0.33 to 0.62 with size while FP goes 0.00 to 1.00, so it fires on bigger work. Rarity itself (not just a fractional bar) matters: a uniform half-the-keywords gate gives FP 0.68 at 3200 words against 0.05 for idf mass at the same fraction.
- Where/why it failed: Three kernel-adjacent claims did not hold as stated. (1) Rarity weighting shifts the size curve; it does not remove it: on topical prose idf mass still fires 0.07/0.28/0.89 at 200/800/3200 words. (2) A genuine edit that hits only the COMMON half of a heading's keywords is missed by the idf gate (recall 0.32-0.38 against 1.00 for the live gate), so rarity buys precision with recall on exactly the generic-looking vocabulary. (3) Idf computed over the headings alone, the literal corpus of open questions, was not useless as I predicted (FP 0.28 at 3200 vs 0.99 raw), and a raw fixed threshold of 4 on unrelated code stayed at FP 0.12 at 3200, below my predicted 0.30. Idf calibrated on prose and applied to code kept FP at 0.15 for 3200 words, above the 0.05 of in-domain calibration.
- Fix: Score by rarity against a background sample of the SAME kind of work being gated, not against the heading corpus; and add co-location: fire only when one 200-word window passes the idf bar, which halved topical-prose FP at 3200 words (0.89 to 0.46) with recall unchanged at 1.00. Keep a small named-term allowlist for a tension whose only discriminating words are common ones, since the rarity bar cannot see it.
- Why this fix: Rarity addresses why long diffs fire (they supply many common words), and co-location addresses why even rare words eventually show up in a big diff (all of them appear somewhere in 3200 words of a topical corpus). The allowlist covers the one measured recall loss. Alternatives measured and rejected: a higher fixed overlap threshold (recall 0.3-0.4 on code) and a headings-only idf (FP 0.28 at 3200).
- Rule of thumb: In this sandbox the size confound was real for every overlap-count gate and shrank but never vanished under rarity weighting; weight by rarity against a same-domain background, score per co-located window rather than per whole diff, and expect to lose recall on edits that only use a tension's common words. Measure the gate's fire rate by diff size before trusting a threshold, because a flat fire rate across sizes is the signal that the gate is reading relevance.
- Provenance (verified/assumed): Verified first-hand: every number above came from the saved sandbox run (real ledger headings, real stdlib source, real prose; the script copies the live gate's keyword rule read-only). The reflex-ack harm in the kernel's last sentence was taken from brain/E46 and brain/E59, and the sandbox never simulated it. Planted edits are synthetic, so recall figures are optimistic about real on-topic diffs.
