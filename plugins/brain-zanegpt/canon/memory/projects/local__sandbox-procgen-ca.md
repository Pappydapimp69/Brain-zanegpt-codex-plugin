## E1 — sandbox procgen ca convergence is not connectivity
- Date: 2026-07-11
- Project: local/sandbox-procgen-ca
- Tags: [algorithm][gamedev][state]
- What: A cellular-automata cave generator (classic "4-5 rule" iterative smoothing of a randomly-seeded grid) was built and run across many seeds/densities to check whether it reliably produces a single connected cave. It does not: at density=0.45 with 6 smoothing iterations, the largest-connected-region fraction across 3 seeds landed at 43.5%, 55.3%, and 61.6% — and the underlying region COUNT (1 vs. 2 vs. 3 separate disconnected caves) stabilized by iteration 2-3 and then stayed fixed for the rest of the run, including out to 15 iterations.
- Why built: A procgen-algorithm sandbox comparing cellular-automata cave smoothing against a known-connected generator (this project's own prior `local__sandbox-maze.md#E1` used a recursive-backtracker spanning tree), to check whether CA smoothing shares the same connectivity guarantee.
- Design: Seed a WxH grid at a fixed wall-probability density; each iteration, recompute every cell as wall if its 8-neighbor wall count exceeds 4, floor if under 4, unchanged if exactly 4 (edges count as wall). Measure connectivity via flood-fill from every floor cell, tracking largest-region size and total region count per iteration.
- Got right: Region count converges FAST and STAYS STABLE — by iteration 2-3 the number of disconnected regions stops changing for the rest of the run (verified out to 15 iterations across 3 seeds), so the algorithm's iteration count doesn't need much tuning for stability, only for connectivity.
- Where/why it failed: Stability is not the same property as connectivity, and the two get conflated. Once the CA process settles into a state with 2 or 3 stable disconnected regions, it STAYS there — there is no mechanism in the smoothing rule itself that merges separate regions once formed, because a cell's next state depends only on its local 8-neighbor wall count, which has no way to "see" that a wall of cells is cutting the map in half. Density sensitivity makes this worse, not better: across 5 seeds each, mean largest-region fraction was 88.5% at density=0.30, dropped to 53.4% (with high seed-to-seed variance: 31%-62%) at density=0.45, and collapsed to 3.2% at density=0.60 — a narrow, steep "sweet spot" where a 15-percentage-point density change swings expected connectivity from over half the map to almost none of it.
- Fix: Not applied to a shipping generator — this was a pure algorithm-behavior sandbox, not a fix to existing project code. The verified, portable takeaway: treat CA-smoothed connectivity as PROBABILISTIC, never assumed, and gate any CA-based cave generator behind an explicit post-generation check (flood-fill for the largest region) with either a reject-and-reseed loop or an active carve-a-corridor repair pass to connect the smaller isolated regions to the main one — the same "verify by construction or by an explicit check, never by density alone" principle this project's own prior maze sandbox established, now independently reconfirmed for a structurally different algorithm.
- Why this fix: A spanning-tree maze generator is connected BY CONSTRUCTION (a tree over N nodes has exactly N-1 edges and one path between any two nodes, mathematically guaranteed) — cellular-automata smoothing has no equivalent structural guarantee, it only has a statistical tendency that gets steadily worse as density rises through the range that also happens to produce the most cave-like (non-degenerate) results, meaning the density range worth using for aesthetics is exactly the range where connectivity risk is highest.
- Rule of thumb: Never assume a cellular-automata (or any local-rule iterative) generator guarantees a global property like connectivity just because its LOCAL behavior (region count, wall density) has visibly stabilized — local convergence and global correctness are different claims, and only an explicit end-to-end check (flood-fill from spawn, not a glance at output) can verify the property that actually matters. This generalizes the lesson from this project's own `local__sandbox-maze.md#E1` finding to a second, structurally unrelated generation algorithm, and adds a concrete additional finding: the density range that best matches CA cave-generation aesthetics (0.40-0.50) is also the range with the steepest, most seed-sensitive connectivity variance — there is no "safe" density that is simultaneously good-looking and reliably connected without a post-check.
- Provenance (verified/assumed): VERIFIED first-hand — ran the actual generator (Node.js sandbox, mulberry32 seeded PRNG) across multiple seeds and densities; exact figures (43.5%/55.3%/61.6% region fractions at density=0.45; 88.5%/75.5%/53.4%/33.1%/14.7%/3.2% mean largest-region fraction across densities 0.30-0.60; region-count stability confirmed out to iteration 15) are direct output of the sandbox run, not estimated or sourced externally.
