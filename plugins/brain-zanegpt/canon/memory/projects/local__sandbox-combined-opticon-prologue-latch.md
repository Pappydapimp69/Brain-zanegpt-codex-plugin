## E1 — opticon prologue latch one primitive
- Date: 2026-08-01
- Project: local/sandbox-combined-opticon-prologue-latch
- Tags: [state][input][gamedev][architecture]
- What: `brain train combined` surfaced Pappydapimp69/Opticon#E28 (a per-turn "bluff" field cleared at end-of-turn was always null by the time the NEXT turn's AI danger check read it — dead branch since shipping; fixed by snapshotting into `lastBluff` immediately before the clear) composed with pappydapimp69/the-game-prologue#E2 (a press+release faster than one frame lands entirely between two per-frame polls and is silently dropped; fixed by capturing presses at EVENT time into a `pending` queue the next poll consumes). A deterministic sandbox confirmed the composed claim: the two recorded fixes are the SAME mechanism at two timescales — a snapshot-before-clear IS a one-slot event-capture queue — and one shared "latch" primitive (producer writes at event time; consumer drains at its own cadence; the producer's lifecycle reset never touches the latch) fixes both recorded bug shapes with no per-case logic.
- Why built: The two lessons were filed in different vocabularies ("snapshot the field before the clear" vs "capture events into a pending queue") for different subsystems (turn-based AI state vs frame-polled input), with nothing connecting them. If they are actually one primitive, a codebase can standardize a single tested latch utility instead of re-deriving an ad-hoc fix per subsystem — and, more importantly, the general audit rule becomes visible: any discrete datum whose producer and consumer sit on opposite sides of a lifecycle reset (end-of-turn clear, per-frame poll boundary, tick queue clear) needs an explicit carry; live reads/polls are only safe for continuously-held state.
- Design: One Python sandbox (no RNG, no wall clock; time is an integer step counter) implementing a single `Latch` class (write-at-event, drain-at-consumer-cadence, untouched by resets) and both recorded shapes: (1) turn-based — bluff set during turn N, live fields cleared at end-of-turn, AI reads during turn N+1; (2) frame-based — scripted keydown at step 5 and keyup at step 6, polls only at steps 4/8 (press+release strictly between polls). Each shape run naive (live read / per-frame state sampling) and with the shared latch.
- Got right: The sandbox reproduces each source lesson's exact recorded failure using its own recorded mechanism — not an analogy: the naive turn variant's AI sees `[]` (opticon#E28's dead branch), and the naive frame variant's poll sees `[]` (prologue#E2's dropped press).
- Where/why it failed: Naive variants: both consumers saw nothing (`[]` / `[]`) — both recorded bugs reproduce. The failure cause is identical in both: the producing side's lifecycle reset (end-of-turn clear; the key being physically up again by poll time) runs before the consumer's read, and the datum was passed as live state instead of being carried across the boundary.
- Fix: The single shared latch primitive fixed both: turn consumer saw `["north"]`, frame consumer saw `["attack"]` — with the same three-property contract in both cases: (1) write happens at the producing EVENT, not lazily; (2) only the consumer's drain clears the latch; (3) the producer's own reset/lifecycle never touches it. Continuous state (held keys, ground-truth facing) stays live-sampled — the latch only carries discrete claims/events, matching both source lessons' own scoping.
- Why this fix: Each source fix was already verified in its own project; the composition's value is the unification — "snapshot-before-clear" and "pending event queue" are one primitive with one ownership rule (consumer owns the clear), so the next occurrence of this bug family (any discrete datum crossing a reset boundary) has a named, standardizable fix instead of a third ad-hoc rediscovery.
- Rule of thumb: When a discrete datum's producer and consumer sit on opposite sides of ANY lifecycle reset (end-of-turn clear, frame-poll boundary, tick queue wipe), carry it in a latch the CONSUMER drains — never a live field the producer's reset clears, and never per-cadence state sampling. One latch utility with "only the drain clears it" as its contract covers the whole family; live reads stay correct only for continuously-held state.
