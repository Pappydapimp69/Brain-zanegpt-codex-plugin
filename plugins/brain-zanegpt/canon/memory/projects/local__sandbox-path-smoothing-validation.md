## E1 — smoothing validation inherits the smoothers blind abstraction
- Date: 2026-07-18
- Project: local/sandbox-path-smoothing-validation
- Tags: [algorithm][pathfinding][testing][gamedev][process]
- What: `brain train group` surfaced the dog + test seam. Composing local/sandbox-dog-pathfinding/E1 (string-pull path smoothing that checks "is this shortcut walkable" against the grid/raw obstacle footprint instead of the real, padded obstacle geometry can cut a corner through an obstacle A* correctly routed around) with pappydapimp69/test/E13 (a check that reuses the code-under-test's own reduced abstraction, or samples incidentally rather than exhaustively, is blind to the bug — a full sweep / independent ground truth catches what spot-checks miss). Built a deterministic sandbox proving the two lessons are the SAME blind-spot shape at one seam: a smoothed path's own validation, if it reuses the smoother's abstraction, cannot see the corner-cut the smoother just introduced.
- Why built: dog-pathfinding/E1 records the smoothing hazard but frames its own defense as "use circle-vs-segment geometry in the smoother"; it does not examine what happens to the VALIDATION/regression check afterward. test/E13 records that spot-check coverage misses divergence between reused code and reality, but from a canvas-animation angle with no pathfinding in scope. Neither text states the general rule both are instances of, nor shows that a *green* post-smoothing collision check can actively certify a clipping path.
- Design: `engine.mjs` (zero RNG, zero wall-clock): obstacle at (5,5), visual radius rv=1.0, agent padding pad=0.6, so true clearance radius R=1.6. A correct A* detour P=[(1,3.7),(4,2.0),(6,2.0),(9,3.7)] clears R everywhere (0 geometry violations). A naive string-pull smoother tests each shortcut's walkability against the RAW footprint (clearance > rv), and collapses P to the straight line (1,3.7)→(9,3.7), which grazes the obstacle at min clearance 1.3 — outside rv=1.0 but inside R=1.6 (a real 0.3-unit clip of the agent's body). Three validators then check the smoothed path: (A) raw-footprint (the smoother's own abstraction), (B) padded geometry but VERTICES-ONLY (incidental sampling), (C) continuous padded geometry (independent ground truth).
- Got right: The A* detour itself is correct in every check — the failure is introduced purely by smoothing and then hidden purely by validation, exactly as the two source lessons predict at their own boundaries.
- Where/why it failed: Validator A reported 0 violations (blind — it uses rv=1.0, and 1.3 > 1.0, the very abstraction gap dog-pathfinding/E1 warns about). Validator B reported 0 violations (blind — the graze is mid-segment at ~x=5, not at either vertex; both endpoints sit >4 units from the obstacle, exactly test/E13's "spot-check frames never hit the broken point"). Only Validator C, checking the continuous segment against the PADDED radius, reported 1 violation. So a smoother with a raw-footprint check plus a raw-footprint or vertices-only regression test ships a path that drives the agent through an obstacle with a fully green collision suite. Byte-identical across two independent `node engine.mjs` runs.
- Fix: A path-smoothing (or any geometry-simplifying) pass must be validated by a check that is INDEPENDENT of the abstraction the pass itself used: continuous segment-vs-obstacle distance against the SAME padded clearance the planner used — never the raw footprint the smoother reused, and never sampled at the path's own vertices (the clip is between them, at the closest-approach point). Add a probe layout deliberately shaped so a shortcut straddles an obstacle (dog-pathfinding/E1), since an incidental map may never produce one.
- Why this fix: The value is turning two separately-scoped observations into one law with a constructed counterexample — a green post-smoothing collision check is worthless if it shares the smoother's abstraction or its sampling. Independent, continuous, padded ground truth is the only thing that certifies the simplified path inherited the planner's correctness.
- Rule of thumb: When a pass SIMPLIFIES a correct output (path smoothing/string-pulling, mesh decimation, waypoint reduction), do not validate it with the same reduced model it used, nor by sampling only its vertices — both inherit its blind spot. Validate against an independent, continuous ground truth at the planner's real (padded) tolerance, and probe with an input deliberately shaped to trigger the disputed shortcut; otherwise a green collision/regression check actively certifies a clipping path.
- Provenance (verified/assumed): VERIFIED first-hand — built and ran `engine.mjs` (deterministic, no RNG/clock); confirmed the correct detour has 0 padded-geometry violations, the naive smoother collapses it to a segment grazing at clearance 1.3 (inside the 1.6 padded radius), validators A (raw footprint) and B (vertices-only) both report 0 violations while validator C (continuous padded geometry) reports 1. Output byte-identical across two separate `node engine.mjs` process invocations.
