## E1 — gc pause cost flips the cache answer from loop size to no cache at a computable crossover
- Date: 2026-10-15
- Project: local/gc-cost-vs-loop-sized-cache
- Tags: [performance][caching][memory][sandbox]
- What: Adding a garbage-collection cost (stop-the-world pause proportional to live cache slots) to the loop-sized cache model keeps the answer binary: best size is 5 (the loop length) until the pause cost per live slot passes a computable crossover, then 0; sizes 1 to 4 were never best at any GC cost from 0 to 399. Crossover was 985 per slot with a collection every 50 accesses and 39.4 with one every 2.
- Why built: Train edge pick: the cache-size lesson says size to the loop and judge by cost under a ceiling, the latency kernel supplies the 1-versus-100 hit/miss cost, and the GC kernel says GC is a tradeoff among competing goals; the pair had not been run together.
- Design: LRU over 1000 accesses cycling 5 items; cost = hits x 1 + misses x 100 + (accesses / accesses-per-GC) x pause-per-slot x live slots; sizes 0 to 8; GC cost swept; crossover computed as miss savings (98,505) over collections x 5 slots.
- Got right: The loop-length answer survives GC: 5 slots saves 98,505 of cost, so only a very large pause flips it; below the loop length extra slots add pause cost with zero hits, so intermediate sizes are never optimal. Size 6 costs 200 more than 5 at pause 10.
- Where/why it failed: My prediction of the crossover was wrong by about 10x: I expected roughly 95 per slot and the exact value at one collection per 50 accesses is 985. GC frequency moves the crossover 25x (39 vs 985). The model is a hand-written cost model: pause linear in live slots, no generational or concurrent collection, and unit costs are abstract, so no real GC was measured.
- Fix: Size the cache to the loop and then check one more number: pause cost per live slot times collection count against the miss saving; treat a cache that is too small as strictly worse than none once GC cost is non-zero.
- Why this fix: Below the loop length a cache gives no hits and only adds live data for the collector to scan, so the choice is between the loop size and no cache; GC changes where the line sits but not that shape.
- Rule of thumb: With GC cost in the model the loop-sized cache wins until the pause per live slot reaches miss savings divided by (collections x slots) (985 per slot at a collection per 50 accesses, 39.4 per 2); below the loop size, none beats a partial cache.
- Provenance (verified/assumed): Verified first-hand by running the sandbox below (sweeps over sizes 0-8, GC cost 0-399, two collection frequencies, a size-6 check). Costs and the linear pause model are assumed constants; no real collector or cache was measured.
