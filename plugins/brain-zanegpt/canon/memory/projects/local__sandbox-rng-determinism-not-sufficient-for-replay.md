## E2 — seeded rng state words save vs count replay and where it stops
- Date: 2026-10-11
- Project: local/sandbox-rng-determinism-not-sufficient-for-replay
- Tags: [determinism][testing][gamedev]
- What: Modelled the seeded-RNG kernel with an sfc32 generator: saving the four state words restored the next 1000 rolls exactly with 0 rolls spent on load, while a seed plus count save was equally exact but cost 400 replayed rolls; the same stream then gave different worlds when iteration order changed and when only the RNG words were restored.
- Why built: The kernel was named in memory prose but never declared as applied, and it claims one stream pays off for saves, replay and lockstep without saying where that stops.
- Design: Python sfc32 with an 8-entity world, 50 ticks of one roll per entity, five scenarios: state-word save, seed plus count save, entity order changed (sorted versus insertion), float sum order of 5000 scaled rolls, and RNG words loaded into a freshly built world.
- Got right: Both save styles were bit-exact (1000 of 1000 rolls) and the cost difference was exactly the roll count, 0 versus 400, growing with play length.
- Where/why it failed: Identical stream state with a different draw order gave a different world, summing the same floats forwards and reversed gave unequal totals, and restoring RNG words into a world that is normally rebuilt by playback produced matching rolls but a different world.
- Fix: Save the world together with the generator words, fix the order in which entities draw (not just the seed), and keep float accumulation out of the authoritative layer or fix its order.
- Why this fix: Each failure kept the roll stream identical, so the stream cannot be the diagnostic; only pinning consumption order and saving all state that rolls act on removed the divergence.
- Rule of thumb: Full state words give O(1) exact RNG restore, but identical RNG state proves nothing about the world: pin draw order, save the world with the words, and keep float sums out of the authoritative layer.
- Provenance (verified/assumed): Verified first-hand by running the sandbox; the generator, world and tick counts are a small toy model, not a real game loop.
- Composed: ideas:SYSTEM/determinism/seeded-rng, sandbox-rng-determinism-not-sufficient-for-replay/E1, sandbox-seed-vs-replay-verification/E1
- Polarity: compatible
- Sandbox: sandboxes/2026-10-11__seeded-rng-state-words-save-vs-count-replay-and-where-it-stops.py
- Prediction: State-word load and seed plus count load both reproduce 1000 rolls exactly with costs 0 and 400; changing draw order keeps equal RNG state but unequal worlds; reversed float sums differ; RNG-only restore keeps rolls equal but worlds differ.
- Observed: RESULT: PASS state-words load 0 rolls vs 400 for seed+count, both exact; same stream gave different world on order change, float sum order, and RNG-only restore
- Scenarios: 1) state-word save and load; 2) seed plus count replay; 3) draw order changed (built to BREAK the one-stream claim); 4) float summation order; 5) RNG words restored into a fresh world

## E1 — seeded rng determinism not sufficient for exact replay of compounding values
- Date: 2026-07-20
- Project: local/sandbox-rng-determinism-not-sufficient-for-replay
- Tags: [determinism][state][testing]
- Composed: pappydapimp69__test/E2, pappydapimp69__the-game-the-recursion/E20
- What: `brain train edge` flagged `test + the-game-the-recursion` as the highest-value untested pair. test#E2 promises that storing a seeded RNG's `{seed,count}` and banning ambient `Math.random()`/`Date.now()` "gives exact save/load, replay, and the lockstep co-op option." the-game-the-recursion#E20 independently found that a compounding formula reconstructed via fold/replay can diverge from a live-sequential computation in float64, purely from computation order, near a specific magnitude crossover — with no RNG involved. Composing them: does test#E2's promise hold even when the value downstream of the perfectly-reproduced RNG stream is itself a compounding formula? Sandbox-confirmed: no — with byte-for-byte identical seed, count, and draw sequence, a live-sequential accumulation and a "logically equivalent" fold/replay reconstruction of the same draws diverge measurably (507,904x the small-scale baseline error at 200,000 compounding operations), and can flip a threshold gate boolean.
- Why built: test#E2 was recorded as a general RNG-determinism discipline, with its own scope explicitly limited to "physics float-nondeterminism must stay out of the authoritative layer" — it doesn't address what happens when a downstream VALUE built from the RNG's draws is itself computed via a different order (live accumulation vs. a replay/reconstruction path). the-game-the-recursion#E20 already demonstrates the divergence mechanism in its own project's specific gate, but doesn't connect it back to test#E2's more general "seed+count is sufficient for exact replay" claim, which is the assumption this composition tests directly. DISTINCT FROM dog#E55 (a similarly-worded prior "test#E2 is necessary but not sufficient" composition): dog#E55's mechanism is SAMPLING-CADENCE dependence — a position-DIFFERENCED velocity changes value depending on how often the observer samples, even with a bit-identical underlying position stream, unrelated to arithmetic grouping. This entry's mechanism is ARITHMETIC-ORDER (associativity) dependence — the SAME fixed sequence of values, sampled at the SAME cadence, diverges purely from which order/grouping the compounding multiplication is carried out in float64. Cadence-dependence and associativity-dependence are two structurally distinct ways "test#E2 is necessary but not sufficient" can be true; this entry is the second one, not a restatement of the first.
- Design: Deterministic Node script (`sandbox_rng_determinism_not_sufficient_for_replay.mjs`), no RNG in the meta sense (a seeded `mulberry32` PRNG is modeled exactly as test#E2 prescribes — same seed always produces the same draw sequence — never `Math.random()`). `liveSequential(draws)` accumulates a compounding growth factor left-to-right, one multiplication per draw, mirroring how a real per-tick game loop would apply each draw as it happens. `replayTreeFold(draws)` reconstructs the SAME final value from the SAME draws via pairwise tree-reduction instead of strict sequential order — mathematically associative in exact arithmetic, not bit-identical in float64. Three scenarios: (A) small draw count (50) — baseline where the two methods agree to float64 precision; (B) large draw count (200,000) — same seed/count/draws, checking whether the divergence grows relative to the baseline; (C) a threshold set exactly between the two large-count values, checking whether it produces opposite gate results.
- Got right: Scenario A confirms the RNG mechanism itself is not at fault and the two computation methods DO agree closely at small scale — this isn't "float64 is broken," it's specifically that error accumulates with MORE compounding operations, exactly the shape the-game-the-recursion#E20 already found in its own live code.
- Where/why it failed: Scenario B: with the identical seed (12345), identical count (200,000), and identical draw sequence feeding both computation paths, live-sequential reached 21950.17429606159 and tree-fold replay reached 21950.17429606125 — a real, nonzero divergence (3.38e-10) that grew 507,904x relative to the 50-draw baseline (6.66e-16), confirming the divergence scales with operation count rather than being a fixed rounding artifact. Scenario C: with a threshold set exactly between two such diverging values (22466.153192998194 vs 22466.153193000027), the live path failed the gate (`false`) while the replay path passed it (`true`) — a real behavioral difference between "what actually happened" and "what a save/replay reconstructs," despite the RNG stream itself being perfectly reproduced in both.
- Fix: test#E2's discipline (store `{seed,count}`, ban ambient randomness) is necessary but not sufficient on its own — any value COMPOUNDING a sequence of RNG draws (repeated multiplication, non-trivial summation, anything order-sensitive in float64) must ALSO be reconstructed via the EXACT SAME computation order the live path used, not merely a "logically equivalent" one. In practice: persist the compounding value itself in the save/replay state directly (not just the seed+count needed to regenerate the draws), or ensure the replay path literally re-runs the same sequential loop the live path used rather than any alternate-order reconstruction.
- Why this fix: test#E2's own scope statement already draws the boundary correctly ("physics float-nondeterminism must stay out of the authoritative layer") — this composition shows the SAME caution applies one layer further in, to any authoritative value that compounds RNG draws through a computation whose order isn't pinned to match between live and replay, which is a distinct risk from the RNG itself being nondeterministic.
- Rule of thumb: "The RNG stream is perfectly reproduced" (test#E2's `{seed,count}` discipline) is a necessary but not sufficient condition for exact replay of anything DOWNSTREAM that compounds those draws — verify the downstream computation's ORDER is pinned identically between live and replay paths too (the-game-the-recursion#E20's crossover-magnitude mechanism), especially for any value that gates or perturbs an outcome (recursion#E17's own composed rule), since a "logically equivalent" reconstruction (a different but mathematically-associative grouping) is not float64-equivalent at nontrivial operation counts.
- Provenance (verified/assumed): Verified first-hand — `sandbox_rng_determinism_not_sufficient_for_replay.mjs` run to completion for all three scenarios, deterministic (a seeded `mulberry32` PRNG, never `Math.random()`, so the same seed always produces the identical draw sequence — confirmed by construction since both `live` and `replay` paths consume the exact same `draws` array), each scenario's computed values, differences, and growth factor printed and checked programmatically (an `allPass` gate across all three; scenario B's first threshold guess was too strict for the actual observed magnitude and was corrected to compare relative growth against the small-count baseline before the final passing run).
