## E1 — sandbox combined brain builder wrong sky version bump blind spot
- Date: 2026-08-29
- Project: local/sandbox-combined-brain-builder-wrong-sky-version-bump-blind-spot
- Tags: [save][determinism][testing][process]
- What: A deterministic sandbox (no RNG, no wall-clock) modeling a PRNG whose behaviour (step() output) is identical pre/post a "content-only" patch, but whose serializer's write path changes from signed-word (brain-builder#E8's exact bug) to normalized-unsigned — swept across 6 fixed seeds, with a canonical-JSON serializer standing in for a real save writer.
- Why built: To test whether brain-builder#E8's mechanism ("identical restored behaviour does not imply canonical serialized form — invisible to any stream or behaviour test") composes with wrong-sky#E18's real-world consequence (a content-only patch without a WORLD_VERSION bump "never reaches a continued save," remedy is a full wholesale save wipe) — specifically, whether the natural, unstated decision procedure for "does this patch need a version bump" (reviewing whether it changes observable BEHAVIOUR) can be fooled by exactly the class of bug E8 already diagnosed, silently shipping a save-breaking change as "content-only."
- Design: Two PRNG implementations sharing an identical `step()` (same LCG, same signed-word semantics feeding callers) but differing serializers — PrePatch writes the raw signed state, PostPatch writes it normalized unsigned (`& MASK32`). Three review procedures run against both, per seed: (1) behaviour_review — compares only step() output sequences, modeling the implied real-world "is this content-only?" check; (2) canonical_form_review — compares serialize() output directly (E8's prescribed fix); (3) old_save_still_loadable — loads a pre-patch save's runtime state into the post-patch code and compares re-saved bytes against the original, modeling wrong-sky#E18's actual failure mode.
- Got right: Swept 6 fixed seeds (1, 7, 42, 999, 123456, 8675309) specifically to confirm the break is a real, seed-dependent mechanism (only fires when the PRNG state's top bit happens to be set at serialize-time — matching brain-builder#E8's stated trigger condition) rather than a universal or coincidental result.
- Where/why it failed: At 2 of 6 seeds (7 and 8675309), the behaviour-based review reported "content-only, no version bump needed" (step() outputs identical, as they always are — the patch never touches step()), while the old-save-reload check showed the re-saved bytes did NOT match the original ({"prngState": -1919864147} vs {"prngState": 2375103149} at seed 7) — a save-format break that a behaviour-only review has no way to see, since it never calls serialize() at all.
- Fix: The version-bump decision cannot be made by behavioural review alone — it must include brain-builder#E8's canonical-form assertion (serialize the same state before and after the patch and diff the bytes directly) as an independent, mandatory check, run across a seed/state sweep wide enough to hit the triggering condition, not just the seeds a manual playtest happens to use.
- Why this fix: The bug is intermittent by construction (only manifests when a specific bit pattern is live in the serialized state at save-time), so a review process that only spot-checks a few seeds/saves — exactly what a human "does this look content-only?" pass would do — can pass clean on the seeds it happens to try and still ship a break that surfaces later on a real player's save. Canonical-form comparison is deterministic per-state and doesn't depend on getting lucky/unlucky with which seed the reviewer picked.
- Rule of thumb: A "does this patch need a save-format version bump" decision made by comparing BEHAVIOUR (replay/fingerprint equality) is structurally blind to brain-builder#E8's exact bug class — it can only be trusted once it also includes an explicit, state-swept canonical-serialized-form comparison, because the two checks disagree on some seeds and behaviour review has no way to notice.
