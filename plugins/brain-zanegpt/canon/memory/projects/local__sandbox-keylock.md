## E1 — key placement must be reachability gated
- Date: 2026-07-05
- Project: local/sandbox-keylock
- Tags: [gamedesign][algorithm][state]
- What: In a generated level with a lock (a gate the player can't cross without an item) and a key placed independently, choosing the key's location uniformly at random over the whole map produces unsolvable levels at a real, non-trivial rate — the key can land in the region only reachable *after* crossing the lock it's meant to open, a circular dependency that softlocks the level.
- Why built: A maze-generation sandbox adding a locked door + key, to check whether "just place both objects randomly" is actually safe.
- Design: Generate a maze (recursive-backtracker spanning tree), pick one of its passages as a locked door, then place a key either (a) uniformly at random over all cells, or (b) restricted to cells reachable from the start with that door treated as impassable.
- Got right: Nothing needed fixing in the maze generator itself — the bug is purely in how objects get placed onto an already-valid map.
- Where/why it failed: "Anywhere on the map" ignores the *order* dependency the lock creates: some cells are only reachable *after* obtaining the key, so placing the key in one of those cells requires already having the key to go get it. A uniform-random placement has no concept of this ordering constraint and will violate it whenever it happens to land there.
- Fix: Compute the reachable set from the start with the lock's edge/door removed (a straightforward flood-fill), and restrict key placement to that set. Generalizes to any "item A is required to reach region B" dependency, not just literal keys — quest items, ability gates, resource-gated progression all need the same reachability filter.
- Why this fix: It directly encodes the constraint that actually matters (can the player reach this placement given their state at this point in the dependency chain) rather than hoping a global random placement happens to respect an implicit ordering it knows nothing about.
- Rule of thumb: Never place a prerequisite object (key, quest item, ability unlock) with plain uniform-random placement over the whole level if a lock/gate depends on it — always restrict candidate placements to the reachable set computed *without* that lock. Verify any "is every level solvable" claim by simulating placement across many seeds and checking reachability, not by eyeballing one generated level.
- Provenance (verified/assumed): Verified first-hand — 2000-trial simulation on 16x16 mazes. Naive uniform-random key placement produced solvable levels only 79.5% of the time (i.e. ~20.5% were softlocked). Reachability-gated placement was solvable in 2000/2000 trials (100%).
