## E2 — wfc no contradiction doesnt mean connected
- Date: 2026-07-13
- Project: local/sandbox-procgen-wfc
- Tags: [gamedesign][map-design][algorithm]
- What: `brain train map-design` (dog... no — sandbox-maze + sandbox-procgen-wfc, both map/tile generators). Composed: `local__sandbox-maze.md#E1` (a global guarantee like map connectivity can't come from local density-tuned rules — needs an explicit construction + flood-fill verification) and `local__sandbox-procgen-wfc.md#E1` (eager fixpoint propagation prevents WFC CONTRADICTIONS — local tile-adjacency rules all satisfiable — across adversarial tilesets). Sandbox-confirmed maze#E1's warning transfers directly: "no contradiction" is a purely local adjacency property and says nothing about global connectivity — a fixed, deterministic, contradiction-free tile assignment can still leave the map's open/walkable region disconnected.
- Why built: sandbox-procgen-wfc#E1 verifies "propagation completeness" (no contradictions) as its success criterion, the same shape of local-rule-based generation maze#E1 already warned about for density-tuned rules — but wfc#E1 was never checked against maze#E1's specific warning, and WFC's local-adjacency constraints (as commonly specified — which tile can sit next to which) don't inherently encode a global connectivity requirement at all.
- Design: `sandbox.py` — zero RNG, zero wall-clock. A fixed 1x5 cell strip with tiles `['O','W','W','W','O']` (two open/walkable cells split by three walls). A toy WFC-style adjacency rule deliberately permissive in the same way a real tile-adjacency table commonly is (O-O, O-W, W-O, W-W all allowed — nothing forbids isolating an open cell). Checked (1) the WFC-style success criterion — no adjacent pair violates the allowed set — and (2) maze#E1's own flood-fill method, applied to just the open cells.
- Got right: sandbox-procgen-wfc#E1's own claim is unaffected and still true — eager fixpoint propagation across the tested adversarial tilesets did prevent contradictions; this composition doesn't dispute that, only what "no contradiction" does and doesn't guarantee.
- Where/why it failed: the fixed tile strip passed the WFC-style check (`True` — no adjacent pair violates the allowed adjacency set) while failing maze#E1's flood-fill connectivity check (`False` — the two open cells are not reachable from each other, separated by an unbroken wall run that is itself perfectly valid under the adjacency rule). A generator that stops at "WFC completed without contradiction" has no evidence the playable space is connected.
- Fix: Not applied to any shipping code (seed/composition entry). Any WFC-style (or other local-constraint) map generator that needs GLOBAL connectivity of its open/walkable space must run maze#E1's flood-fill check as a separate, explicit post-generation step — "no contradiction" and "connected" are independent properties that must each be verified on their own terms, exactly as maze#E1 already prescribes for density-tuned generation.
- Why this fix: This closes a real blind spot rather than inventing one — sandbox-procgen-wfc#E1's own recorded success criterion (contradiction-free) is legitimate for what WFC promises (local tile-adjacency satisfiability) but was never flagged as insufficient for a DIFFERENT property (global connectivity) that a map generator commonly also needs; maze#E1 already has the right verification method, it just wasn't connected to WFC's use case until now.
- Rule of thumb: "No contradiction" (every local adjacency/constraint rule satisfied) and "connected" (the playable space is one reachable region) are independent properties for ANY constraint-based map/tile generator, not just density-tuned ones. A contradiction-free WFC-style result needs its own explicit flood-fill (or equivalent global-reachability check) if connectivity matters — completeness of local propagation is not evidence of it.
- Provenance (verified/assumed): Verified first-hand — built `sandbox.py` (zero RNG, zero wall-clock, fixed 5-cell strip, fixed tile assignment, fixed adjacency rule), confirmed the WFC-style no-contradiction check passes (`True`) while the flood-fill connectivity check fails (`False`) on the identical fixed input. Confirmed deterministic/reproducible across two independent process invocations of `python3 sandbox.py`, output diffed byte-identical.

## E1 — sandbox procgen wfc eager propagation prevents contradictions
- Date: 2026-07-11
- Project: local/sandbox-procgen-wfc
- Tags: [algorithm][gamedev][testing]
- What: A minimal Wave Function Collapse (WFC) implementation (lowest-entropy-first cell collapse, full constraint propagation to a fixpoint after every collapse, no backtracking) was tested against three progressively adversarial tile-compatibility structures — a 5-tile linear-order gradient, the same set plus a deliberately narrow "bottleneck" tile (compatible with almost nothing, weighted up to 20x to force frequent selection), and an 8-tile directional edge-socket ("pipe"/circuit) tileset — expecting to observe and characterize real contradiction (dead-end) rates. The measured contradiction rate was 0% across all three tilesets, every grid size tested (3x3 through 14x14), and hundreds of trials per configuration.
- Why built: A procgen-algorithm sandbox to characterize how often naive (no-backtracking) WFC actually produces an unrecoverable contradiction, since backtracking/restart-on-contradiction is commonly presented in WFC tutorials/discussions as an assumed-necessary production requirement.
- Design: Grid cells hold a Set of possible tile indices. Each step: find the uncollapsed cell with the fewest remaining options (lowest entropy), collapse it to one option (uniform-random or weighted), then propagate the constraint via a BFS queue that keeps expanding to newly-narrowed neighbors until nothing changes anywhere (a true fixpoint, not a single-hop update). A contradiction is any cell whose possibility set is reduced to zero.
- Got right: The core hypothesis going in — "some tileset structure will produce measurable contradictions" — was reasonable and worth testing empirically rather than assuming from tutorials; testing three genuinely different adversarial structures (rarity-weighted bottleneck, then a structurally different directional-socket tileset) rather than stopping after the first null result gave more confidence the 0% finding wasn't a fluke of one specific tileset.
- Where/why it failed: The hypothesis was wrong for the tested cases — no contradiction was ever observed, at any grid size (up to 14x14 = 196 cells) or tileset tested, including a tileset with a deliberately narrow bottleneck tile weighted 20x to force it to appear often. Tracing why: the BFS-to-fixpoint propagation step is doing far more preventive work than the "propagate to immediate neighbors only" shortcut some naive/tutorial WFC implementations use — when a shared cell's possibility set narrows because of one neighbor's collapse, that narrowing itself gets propagated onward to ITS other neighbors before they're ever chosen for collapse, proactively removing options that would have led to a dead end, rather than only discovering the conflict after both neighbors are already committed.
- Fix: Not applicable — no bug was found to fix, this is a characterization result, not a bug report. The verified, portable takeaway: before adding backtracking/restart-on-contradiction complexity to a WFC implementation, verify the propagation step is actually EAGER (propagates to a full fixpoint every collapse, cascading through however many cells are affected) rather than a single-hop update — a shortcut that looks equivalent in casual testing but leaves genuine holes that eager propagation would have closed.
- Why this fix: Backtracking/restart machinery is real implementation complexity (state snapshotting, retry budgets, potential infinite-loop risk on a truly unsatisfiable tileset) that this sandbox's results suggest may be unnecessary overhead for many realistic 2D grid tilesets if propagation is implemented correctly and fully — the actual bug to hunt for, if contradictions ARE observed in a real project, is more likely an incomplete propagation step than an inherently contradiction-prone tileset.
- Rule of thumb: Don't assume WFC needs backtracking/restart-on-contradiction as a baseline requirement — first verify propagation is eager and complete (BFS/queue-based, cascading to a fixpoint after every single collapse, not a one-hop neighbor update), and only add recovery machinery if contradictions are still empirically observed after confirming that. Distinguish this from a genuinely unsatisfiable tileset (some adjacency constraint sets have no valid global solution for a given grid shape at all, which no amount of propagation completeness fixes) — this sandbox did not find or test that harder failure case, so it remains open whether a maximally adversarial tileset (e.g. one with a provably-required-but-impossible boundary condition) can still break eager propagation; treat the 0%-contradiction finding as scoped to the three tileset structures actually tested, not a universal guarantee.
- Provenance (verified/assumed): VERIFIED first-hand — ran all three tileset configurations (Node.js sandbox, mulberry32 seeded PRNG) across grid sizes 3x3 to 14x14, 200-300 trials per configuration, 0/N contradictions in every single run recorded. The scoping caveat (this doesn't prove all tilesets are contradiction-free) is an explicit acknowledged limit of what was tested, not an extrapolated claim.
