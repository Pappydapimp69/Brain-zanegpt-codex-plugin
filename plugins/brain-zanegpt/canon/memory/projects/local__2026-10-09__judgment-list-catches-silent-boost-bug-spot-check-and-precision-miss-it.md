## E1 — judgment list catches silent boost bug spot check and precision miss it
- Date: 2026-10-09
- Project: local/2026-10-09__judgment-list-catches-silent-boost-bug-spot-check-and-precision-miss-it
- Tags: [search][testing][evaluation][regression]
- What: In a tiny deterministic lexical engine, a silent tags-field boost bug (decoys whose tags carry the query word outrank real hits, present for 3 of 10 topics) passes a manual spot-check of the first 3 queries, is caught by a judgment list on MRR (1.000 to 0.850) and nDCG@5 (0.998 to 0.903), and first shows on nDCG@5 at a list of 4 queries; a second silent body-boost bug that only reorders hits inside the top 3 leaves precision@3 and MRR unchanged and is caught only by nDCG@5 (0.998 to 0.843).
- Why built: The judgment-list kernel says relevance bugs never error and only a graded list catches them, and the ranking-metrics kernel says the metrics measure different things; neither was tested together on bugs that differ in where they bite, nor was the minimum list size measured.
- Design: 10 topics with a main doc (title plus body tf 3, grade 3), a secondary doc (body tf 5, grade 2), a tangent (tf 1, grade 1) and a decoy with the query word only in tags for topics 3, 5, 8; score is tf times field boost, ties broken by id; metrics P@3, MRR, nDCG@5 against the graded list; spot-check means the top hit is relevant for the first 3 queries; BUG_A tags boost 0.5 to 6, BUG_B body boost 1 to 5; a sweep of judgment-list prefix length 1 to 10.
- Got right: Spot-check passed for both bugs on queries 0-2 while BUG_A hurt 3 of 10 queries; MRR and nDCG caught BUG_A and only nDCG caught BUG_B; precision@3 was blind to BUG_B (1.000 vs 1.000 in the BUG_B run) and the smallest list that exposed BUG_A was 4 queries, the first decoy topic.
- Where/why it failed: My first fixture was wrong, not the claim: titles named other topics so unrelated docs outranked real hits under the correct boosts (good P@3 0.333) and BUG_B accidentally improved nDCG to 1.0; I rebuilt it with neutral titles and a higher body tf in the secondary doc. Baseline precision@3 stays 0.900 because the decoys already sit in the top 3 for 3 topics even with correct boosts, so BUG_A shows on MRR and nDCG, not on precision@3.
- Fix: Gate relevance changes on a judgment list scored with nDCG (graded) plus MRR, and make sure the list covers every query class that has a decoy-prone field, instead of sampling a few queries by eye or gating on precision@k alone.
- Why this fix: The detection depends on whether the list includes the queries where the bug bites; here the list needed 4 of 10 queries, so the list size is set by the rarest affected query class, and the set-based precision metric cannot see a reorder inside its window.
- Rule of thumb: A silent relevance bug is found by a judgment list only if it contains a query from the affected class and uses a position-aware graded metric: spot-checking 3 queries and gating on precision@3 both missed bugs that nDCG@5 caught (here, in a 10-topic, two-bug model; not claimed for real engines).
- Provenance (verified/assumed): Verified first-hand by running the shipped sandbox (RESULT: PASS) after fixing a fixture error found on run 1; this is a hand-built model, not Elasticsearch or a real index, and the 20-30 query guidance for chunk-size evaluation is touched here only as the list-size sweep.
