## E1 — hybrid gate windowed rarity allowlist recall vs size
- Date: 2026-10-10
- Project: local/sandbox-hybrid-keyword-gate
- Tags: [tooling][process][testing][search]
- What: Tested whether a hybrid relevance gate (windowed co-location, rarity weighting, plus either a per-tension named-term allowlist or a weakest-keyword floor on the bar) can keep recall >= 0.90 on common-word edits and false fires <= 0.10 at 3200 words, so the recall-for-precision tradeoff would be avoidable. It cannot on topical prose: 0 of 45 configs (5 window widths x 9 gate variants) pass on the ideas repository text, and the configs that pass on code (11) or off-topic prose (7) are only the narrowest windows, which fail on edits whose common words are spread over a sentence.
- Why built: Open tension 'Should a relevance gate over prose trade recall of common-word edits for precision on large diffs?' came from the earlier size sweep (sandbox-keyword-gate-rarity/E1): whole-diff idf mass cut false fires to 0.05 but recalled a common-word edit only 0.32-0.38, and on topical prose windowing only reached 0.46. That entry's own fix list named windows plus a small allowlist, never measured together. Supports pole A of tension 'Should a relevance gate over prose trade recall of common-word edits for precision on large diffs?' in a limited sense: the tradeoff cannot be engineered away on prose, and the recall-preserving settings fire on 20-74% of 3200-word prose diffs, which the kernel says turns the gate decorative, so precision is the safer default for large prose diffs; pole B holds only for small windows on off-topic diffs or when the missed fire is costly enough to accept a prose false-fire rate of 0.2 or more.
- Design: Same 79 real ledger headings and live-gate keyword extraction as E1 (read-only). Three corpora, each split in halves (first half calibrates idf at the window scale, second half supplies diffs): Python stdlib source (code), Python language-reference prose (off-topic prose, 23 diffs at 3200 words), ideas repository prose (topical control, 69 diffs). A diff fires if ANY of the 79 tensions fires in ANY window (width 200/100/50/20/10, stride half). Bars: idf mass >= half the heading, floor (mass of the heading's common half), floor2 (floor plus >= 2 distinct keywords). Allowlists: curator-blind (2 keywords rarest across the ledger) and oracle (2 keywords from the edit's own common half), each as an OR with a pair-in-one-window rule. Plants replace words in the diff: the common half of a heading's keywords as one block, spaced 4 words apart, spaced 10 apart, and dispersed evenly across the whole diff; a rare-half block as sanity. Windowed recall is attributed to the edit's own windows only. Whole-diff live and idf baselines kept for reference.
- Got right: The windowed floor bar does what it was built for: common-block recall is 1.00 at every size and rare-block recall 1.00. Windowing also removes most of the size growth for the idf bar (code false fires 0.01 at 3200 words, versus 0.96 for the live whole-diff gate), and a narrower window lowers false fires monotonically on every corpus (ideas floor: 0.74 / 0.54 / 0.39 / 0.32 / 0.23 at W=200/100/50/20/10; code floor: 0.34 / 0.18 / 0.14 / 0.07 / 0.03). On code the floor bar at W=20 passes both targets for block and 4-spaced edits (false fires 0.07, recall 1.00 / 0.96).
- Where/why it failed: (1) On topical prose no config meets both targets: lowest false-fire rate with block recall >= 0.90 is 0.20 (floor2, W=10, which also drops the 4-spaced edit to 0.36), and highest block recall with false fires <= 0.10 is 0.42. The hybrid levers move along that frontier rather than off it. (2) Narrowing the window to buy precision is paid for in edit shape: floor at W=10 recalls a 4-spaced edit 0.34-0.36 on every corpus and a 10-spaced edit 0.00; at W=20 a 10-spaced edit falls to 0.34-0.37; so the tradeoff relocates to how tightly a real edit co-locates its words, which no corpus statistic tells you. (3) Edits dispersed across the 3200-word diff are recalled at <= 0.07 by every windowed gate with W <= 100, versus 1.00 for the whole-diff live gate (whose false fires are 0.96-1.00). (4) The allowlists did not help as hoped: curator-blind pairs added little (idf bar block recall 0.33 -> 0.35 on ideas at W=50; 0.59 -> 0.66 on off-topic prose), and oracle pairs buy recall 1.00 at a false-fire price (code W=50 0.00 -> 0.24, ideas 0.20 -> 0.48). The floor2 refinement barely helps (ideas W=50 0.39 -> 0.35). (5) Seven of my sub-predictions missed, mostly in the direction of narrower windows being kinder than I expected (spread4 recall at W=20 stayed 0.96, not <= 0.60).
- Fix: Do not rely on a single size-blind gate to carry both goals. For a tension whose wording is only common vocabulary, give it its own narrow, floor-style rule (W about 20 words, floor2 bar) and gate it on small hunks, accept that prose-heavy diffs will fire it at roughly 0.2-0.3, and keep rarity-weighted whole-diff scoring for the tensions with rare nouns. Report the gate's fire rate by diff size and by corpus kind (code, off-topic prose, topical prose) before choosing the window, because the same config is feasible on one and infeasible on another.
- Why this fix: The sweep shows the false-fire rate at 3200 words scales with how many windows the diff supplies and how common the tension's words are in that kind of text, while recall of a common-word edit scales with window width; a per-tension window and bar is the only measured lever that moves a tension along that curve independently of the others. Alternatives measured and rejected: one global hybrid (no config feasible on topical prose), curator-blind allowlists (about +0.02-0.07 recall), oracle allowlists (full recall at roughly double or more the false fires), and whole-diff live scoring (full recall of dispersed edits but 0.96-1.00 false fires).
- Rule of thumb: In this sandbox the recall-for-precision tradeoff for common-word edits was relocated by windows, rarity bars and allowlists, never removed: on topical prose at 3200 words the best a hybrid did was false fires 0.20 with block recall 1.00 or recall 0.42 with false fires 0.07. Treat a claim that a hybrid gate escapes the tradeoff as unproven until it is measured on three kinds of text (code, off-topic prose, topical prose) with three edit shapes (contiguous block, spread over a sentence, dispersed across the diff); a gate tuned on code alone looked feasible here and failed on the prose.
- Provenance (verified/assumed): Verified first-hand: every number above is from the saved sandbox, which was run three times with byte-identical output (real ledger headings, real stdlib source, real language-reference prose, real ideas prose; keyword rule copied read-only from the CLI). Planted edits are synthetic, so recall is optimistic about real diffs; floor-bar recall of 1.00 on the common-half block is close to true by construction; the off-topic prose sample is small (23 diffs at 3200 words, so the 0.09 false-fire rate is within sampling noise of the 0.10 line); firing on topical prose may be partly legitimate, so prose false fires are an upper bound. The harm of reflex acknowledgement comes from the kernel text and E1, outside what this sandbox exercised.
