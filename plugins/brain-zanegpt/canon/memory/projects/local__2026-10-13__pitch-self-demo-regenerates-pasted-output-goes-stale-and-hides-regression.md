## E1 — pitch self demo regenerates pasted output goes stale and hides regression
- Date: 2026-10-13
- Project: local/2026-10-13__pitch-self-demo-regenerates-pasted-output-goes-stale-and-hides-regression
- Tags: [presentation][credibility][pitch][sandbox][model]
- What: A toy word-count tool through six versions, with its pitch document as the demo input, compared across three ways of showing evidence: a pasted version-1 output, a pasted output with a version stamp, and a demo regenerated by running the current tool on the pitch itself at build time.
- Why built: The kernel says to pitch a tool by running it on its own creation so the evidence is first-party and real; the stored lesson on pasted output says a pasted real output goes stale silently. I wanted to see what the self-demo adds and where it stops being a pure win.
- Design: One fixed pitch text that contains a tab and a hyphenated phrase; tool v1 counts lines, v2 non-blank lines, v3 words, v4 words but crashes on a tab, v5 fixes the crash, v6 splits hyphenated words. Per version: does each strategy show what the current tool prints, and does it claim success.
- Got right: Pasted output matched the current tool in 1 of 6 versions; the stamp flagged all 5 stale versions yet still displayed the old number; the build-time demo was fresh in 6 of 6 (by construction, since it is regenerated from the current tool).
- Where/why it failed: Version 4 crashes on the pitch document itself. The pasted snapshot still claimed success in 6 of 6 renders while truth was 5 of 6, so it hid the regression; the self-demo exposed it in exactly 1 render, which means a regenerated demo helps credibility only if the build gate treats an error output as a failed build and not as pitch copy.
- Fix: Generate the evidence block from a run of the current tool on the pitch itself, store the producing command and version beside it, and fail the build when the run errors or its output differs from a frozen expectation.
- Why this fix: Regeneration removes the staleness the stamp can only report, and the error gate turns the self-demo's one real weakness, a crash on its own input, into a caught defect instead of a published claim.
- Rule of thumb: A self-demo keeps evidence current only when it is regenerated and gated on success; a pasted or merely stamped output is stale after the first version bump and can hide a crash on the tool's own input.
- Provenance (verified/assumed): Verified first-hand by running the sandbox; the tool is a six-version toy, freshness of the regenerated demo is true by construction, and no real pitch audience or real tool was tested.
