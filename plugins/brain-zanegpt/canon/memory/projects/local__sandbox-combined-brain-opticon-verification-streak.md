## E1 — sandbox combined brain opticon verification streak
- Date: 2026-08-29
- Project: local/sandbox-combined-brain-opticon-verification-streak
- Tags: [process][verification][deploy][method]
- What: A deterministic sandbox (no RNG, no wall-clock sleeps) modeling a "reported success" pipeline step (a push/sync log, or a deploy Action) against a destination that either lags before propagating, flaps between live/stale reads even after propagating, or genuinely never converges.
- Why built: To test whether brain#E21 ("N pushed, 0 held" self-reported by the pusher is not itself promotion — acceptance runs async and writes its real verdict where nobody looked) and opticon#E8/#E13 (a deploy Action reporting success doesn't mean the URL is live yet; one clean CDN check is a single edge node's state, not proof of convergence — require a streak) are really the SAME underlying failure mode when composed, or just two superficially similar but mechanically distinct bugs.
- Design: Three verification strategies run against the same simulated destination: (1) naive — trust the pusher's own "done" report and never read the destination; (2) single-read — read the destination exactly once after reporting; (3) streak — read repeatedly, require N consecutive successful reads before declaring convergence, with a max-read ceiling to also correctly detect genuine non-convergence.
- Got right: The streak strategy was designed to serve double duty — both waiting out a propagation delay (brain#E21's shape) and being resistant to post-propagation flap (opticon#E13's shape) — using one mechanism (a consecutive-success counter with a ceiling) rather than two separate fixes.
- Where/why it failed: Naive verification reported LIVE=True in all three cases, including the genuine-failure case where the destination never actually converges — confirming it is not verification at all, just an echo of the pusher's own claim. Single-read verification was shown to be flappable: scanning read start-offsets against a realistic post-propagation flap pattern, at least one valid post-propagation read still lands on a transient False even though the target is genuinely, eventually live — so "I checked once and it was there" is not proof either.
- Fix: Streak verification (>=3 consecutive successful independent reads of the actual destination, bounded by a max-read ceiling) correctly reported LIVE only in the two cases that actually converge (waiting out both the propagation-delay case and the post-propagation-flap case), and correctly reported FAILED — not a false positive — in the case that never converges.
- Why this fix: A single check (or zero checks, i.e. trusting the reporter) collapses two distinct real-world defects — async propagation lag and post-propagation edge inconsistency — into indistinguishable-looking "it said success" states. A streak requirement with a ceiling is the minimal mechanism that resolves both without needing to know in advance which failure mode you're facing, and still terminates (as FAILED) instead of polling forever when the destination genuinely never converges.
- Rule of thumb: Never trust a pipeline step's own self-reported success as proof the downstream effect landed (push logs, sync summaries, deploy Action green checks) — independently re-read the actual destination. And never trust a single read of that destination either — require a short streak of consecutive independent reads across real time before calling it converged, with an explicit ceiling so a genuine failure is reported as failed rather than polled forever.
- Provenance (verified/assumed): Verified first-hand — ran the sandbox (python3 /tmp/claude-0/-home-user-Collective/03220183-5f9d-542d-a9df-b5021c043261/scratchpad/edge-sandbox/sandbox.py) across three deterministic cases (async-lag-then-stable, post-propagation-edge-flap, genuine-failure-never-propagates) and confirmed all three assertions: naive always echoes True even on real failure; single-read is provably flappable on a genuinely-live target; streak verification correctly distinguishes eventual convergence from genuine non-convergence. brain#E21 and opticon#E8/#E13 were read directly via `brain query brain --verbose` and `brain query opticon --verbose` before designing the sandbox, not assumed from memory.
