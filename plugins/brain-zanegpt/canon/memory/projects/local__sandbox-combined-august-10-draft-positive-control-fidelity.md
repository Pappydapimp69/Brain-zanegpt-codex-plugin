## E1 — sandbox combined august 10 draft positive control fidelity
- Date: 2026-08-29
- Project: local/sandbox-combined-august-10-draft-positive-control-fidelity
- Tags: [testing][harness][method][debugging]
- What: A deterministic sandbox (no RNG, no wall-clock) modeling a closed-vocabulary capture layer that silently drops one event type, a correct predicate waiting on that event, a broken predicate (wrong field name, unrelated bug), and august-10#E20's positive-control discriminator applied at two fidelity levels against the synthetic state it constructs.
- Why built: To test whether august-10#E20's diagnostic technique — "timed out but looks healthy" is ambiguous between a broken predicate and a silently starved upstream layer; discriminate by running the predicate against a synthetic state built to satisfy it — actually resolves cleanly when applied to draft#E9's specific bug shape (a closed-vocabulary capture layer dropping a new UI zone's click before the resolver ever sees it), and whether the discriminator itself has a failure mode.
- Design: Three scenarios run against the same predicate/capture-layer machinery: (A) correct predicate + real starved capture layer (draft#E9's shape), positive control built with full fidelity to the real capture layer's event shape; (B) broken predicate (dog#E97 shape, checks wrong field name) with an open vocabulary so the capture layer itself is not the bottleneck, isolating the predicate defect; (C) the stress test — same real bug as (A), but the positive control is built LAZILY, omitting fields ('zone', 'ts') the real predicate actually checks, keeping only the field a human would think to verify first ('type').
- Got right: Cases A and B confirm the discriminator works exactly as august-10#E20 describes — a full-fidelity synthetic state correctly clears the predicate and points at the capture layer (A), and correctly implicates a genuinely broken predicate (B), when both scenarios produce the identical outward symptom (timeout, no exception).
- Where/why it failed: Case C reproduces a real failure mode of the discriminator itself: a positive control built with only the field a human would naturally think to check first ({'type': 'newzone_click'}, omitting 'zone' and 'ts') makes the CORRECT predicate return False against it — identical to the broken-predicate verdict in case B — even though the predicate is completely fine and the real bug is upstream in the capture layer. The discriminator misdirects debugging effort toward "fix the predicate" when the actual fix is "widen the capture layer's vocabulary."
- Fix: The positive control's synthetic state must be built with the SAME fidelity as what the real upstream layer would actually emit (every field the predicate reads, not just the field that makes the bug narratively obvious) — not a hand-typed minimal stand-in. In practice: construct the synthetic event by copying/mutating one real captured event of a similar type, or by asserting the synthetic event's shape against the same schema/type the real capture layer emits, rather than writing it from scratch.
- Why this fix: A positive control is only as trustworthy as its fidelity to the real upstream output — an under-specified control can silently reproduce the exact same "returns False" symptom as a genuinely broken predicate, so the discriminator's own output is not self-verifying; the fidelity of the synthetic state has to be established independently (schema match, or derived from a real captured event) before its verdict can be trusted.
- Rule of thumb: When applying an in-context positive control to discriminate "broken predicate" from "starved upstream layer" (august-10#E20's technique), never hand-write the synthetic state from memory of what fields "should" matter — derive it from the real upstream component's actual output shape (a schema, a captured real event, a fixture), or the control can silently give the same false verdict the technique exists to rule out.
- Provenance (verified/assumed): Verified first-hand — ran the sandbox (python3 /tmp/claude-0/-home-user-Collective/03220183-5f9d-542d-a9df-b5021c043261/scratchpad/edge-sandbox2/sandbox.py) across three scenarios and confirmed: (A) full-fidelity control correctly clears the predicate in the starved-capture-layer case; (B) the control correctly implicates a genuinely broken predicate; (C) a lazily-built control gives a false-negative verdict on the SAME real bug as (A), reproducing a concrete failure mode of the discriminator itself. august-10#E20 and draft#E9 were read directly via `brain query august-10 --verbose` and `brain query draft --verbose` before designing the sandbox, not assumed from memory.
