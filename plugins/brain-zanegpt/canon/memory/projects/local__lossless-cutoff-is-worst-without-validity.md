## E1 — lossless cutoff is worst without validity
- Date: 2026-10-15
- Project: local/lossless-cutoff-is-worst-without-validity
- Tags: [gamedev][input][state][testing]
- What: Composed the lossless-cutoff rule (cutoff on top of validity loses nothing at the
  largest valid lag) with the one-sided gate formula ((N/P) times lag invalid presses when
  a gate skips validity), and found the same cutoff is best for one policy, worst for the other.
- Why built: Weakest-link train pick: the two entries share five tags and both describe an
  age cutoff on period-W legality, but no lesson had run them on one wave to see whether
  their cutoff advice agrees.
- Design: legal(t) = t mod P < W; a hint names B if B was available when issued, else A
  (always legal); invalid at use iff it names B and B is now unavailable. P 10, W 3, 600
  uses per lag, lags 1, 2, 4, 6, 9. Cutoff scanned 0 to 10 under validity+cutoff and gate-only.
- Got right: Validity+cutoff became lossless first at cutoff 9, the largest valid lag, as
  the first entry says; gate-only invalid executions rose monotonically with the cutoff
  and hit their maximum, 600, at that same cutoff 9.
- Where/why it failed: The gate formula (N/P) times min(lag, W) missed lag 9: 60 invalid,
  not 180. Iteration 2 found the exact count is (N/P) times min(L, W, P-L, P-W) for every
  lag 1 to P-1 on P10W3, P12W5 and P15W7, so the formula's scope limit is P-L as well.
- Fix: Never carry a cutoff from a validity-guarded design to a gate that skips validity:
  there the lossless cutoff executes every stale press it admits; pick the gate's cutoff
  from the invalid count min(L, W, P-L, P-W) per lag, or add the validity check.
- Why this fix: With validity the cutoff only removes valid presses, so higher is safer;
  without it the cutoff is the only filter, so higher admits more invalid presses, and the
  two advices point in opposite directions on the same number.
- Rule of thumb: A cutoff tuned to be lossless with a validity check is the worst cutoff
  for the same gate without it; per-lag invalid presses are (N/P) x min(L, W, P-L, P-W).
- Provenance (verified/assumed): verified first-hand by the sandbox below; one lag set for
  the cutoff scan, three period shapes for the closed form; one-sided legality only.
- Composed: age-cutoff-lossless-threshold-exceeds-period-p12/E1, sandbox-one-sided-formula-explains-gate-invalid-counts/E1
- Picked-by: current-half
- Sandbox: sandboxes/2026-10-15__lossless-cutoff-is-worst-without-validity.py
- Prediction: Written before running: lossless first at cutoff 9; gate-only invalid count
  monotonic in the cutoff; (N/P) x min(L, W) holds for lags up to P-W and misses lag 9.
- Observed: RESULT: PASS lossless cutoff 9 is the worst gate-only cutoff (600 invalid =
  max); monotonic; formula matches 1, 2, 4, 6, misses 9; refined min(L,W,P-L,P-W) exact
  on 3 shapes.
- Scenarios: 1) cutoff scan with validity; 2) cutoff scan gate-only; 3) lag 9 beyond P-W,
  built to break the gate formula; 4) closed form over all lags on three period shapes.
