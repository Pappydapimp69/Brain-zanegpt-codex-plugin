## E1 — two futures timelapse fit min axis and composite filter cost
- Date: 2026-10-09
- Project: local/2026-10-09__two-futures-timelapse-fit-min-axis-and-composite-filter-cost
- Tags: [viz][canvas][animation][mobile][testing]
- What: A two-panel "two futures" growth time-lapse built on a golden-angle spiral clips 68 percent of its nodes on a portrait side-by-side layout (207x896 panels) when the fit scale uses height alone, and overruns a 600-unit frame budget on 88 of 101 frames when every node carries its own glow filter; fitting to min(W,H) clips 0 and one composited filter pass overruns 0 frames at 400 nodes.
- Why built: The kernel for the commons time-lapse was filed but never rebuilt; this checks that it composes with the min-axis fit lesson and the growth-batch filter-cost lesson instead of failing on a phone.
- Design: Two panels with the same t0 counter of 1; take-only stays at 1, contribute grows to 401 over 101 frames; nodes at radius sqrt(i) and angle i times the golden angle (no RNG, so replays hash identical); clip counts per layout for H-only versus min(W,H) scale; frame cost per-mark = n*(1+11) versus composite = n + 11 against a budget of 600; a break case at 1000 nodes.
- Got right: Counters match at t0 and end 1 versus 401, two replays are byte-identical, min-axis fit clips 0 in all three layouts, and the composited pass keeps the contribute panel under budget at 400 nodes while per-mark glow first overruns at frame 13 (53 nodes).
- Where/why it failed: The composited pass is not a cure for unbounded growth: at 1000 nodes its cost is 1012 against 600. Also a stacked portrait layout (414x448) showed no clipping even with the height-only formula, because min(W,H)=414 and H=448 differ little, so that layout hides the bug.
- Fix: Fit each panel to min(panel width, panel height), draw nodes unfiltered and apply the glow once per panel per frame, and cap or thin the node count so n + filter stays inside the frame budget.
- Why this fix: Fit is bounded by the shorter panel axis, and a per-mark filter turns linear growth into a late-movie overrun that the take-only panel never shows, so only the growing panel breaks.
- Rule of thumb: In a diverging-growth pitch animation, test the layout where panel width is the short axis (side-by-side portrait), not just stacked or landscape, and composite the glow per panel; compositing moves the cliff from about 50 to about 590 nodes at these unit costs but a node cap is still needed.
- Provenance (verified/assumed): Verified first-hand by running the shipped sandbox (RESULT: PASS); unit costs and the budget are my own model values, not measured canvas timings, so the node counts are relative, not real-device figures.
