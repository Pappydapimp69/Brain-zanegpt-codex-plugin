## E1 — seeded rng state words vs count and stream splitting
- Date: 2026-10-12
- Project: local/sandbox-seeded-rng-state-words
- Tags: [gamedev][state][determinism][testing][sandbox]
- What: A stdlib sfc32 sandbox over 8 fixed seeds applying the seeded-rng kernel. Saving the four state words reloaded exactly 8/8 at a cost of 4 word copies, while a seed-plus-count replay (49,999 rolls) diverged 8/8 once one draw bypassed the counter. One extra roll in a single shared stream changed the next combat roll 8/8 and shifted every later roll by one; with per-subsystem streams an extra spawn roll changed it 0/8, but an extra roll inside the combat stream itself still did 8/8.
- Why built: The kernel says to save state words rather than a seed and count, and prologue E1 and E19 recorded the same family of issues (state-word saves, and a quest-driven spawn roll perturbing a shared stream), but nothing separated the O(1) benefit from the correctness benefit or tested what stream splitting does and does not fix.
- Design: sfc32 with a 12-draw warm-up and seeds mixed through sha256 (so a subsystem name yields an independent stream); a counter that only counts draws made through the counted path; save and reload via state words versus fresh seed plus replay of the saved count; a control where every roll is counted; one timeline with an inserted roll before 6 combat rolls versus one without.
- Got right: All five written predictions held: 8/8 exact state-word reload, 8/8 count-replay divergence with one uncounted draw, 8/8 control exactness when every roll is counted, 8/8 shared-stream perturbation with an exact one-position shift, 0/8 with split streams.
- Where/why it failed: Nothing was refuted. The break case shows the limit: splitting streams only isolates one subsystem from another, so any change in how many rolls a subsystem makes still shifts that subsystem's own later rolls 8/8.
- Fix: Save the generator's state words, not a count; give each subsystem that can gain or lose rolls conditionally (spawning, cosmetics) its own derived stream; keep rolls that change the outcome in a stream whose roll count is itself deterministic from the command log.
- Why this fix: State words make a load independent of the counter's bookkeeping and cost 4 words instead of 49,999 rolls; split streams remove cross-subsystem perturbation but do nothing for in-stream insertions, so the log-determinism rule is still required.
- Rule of thumb: Save PRNG state words, not seed plus count: it was both O(1) and the only exact form once one draw bypassed the counter. Derive a separate stream per subsystem whose roll count varies, but expect a roll added inside the same stream to shift all of its later rolls. Tested on sfc32, 8 seeds and one insertion point, not on a real engine.
- Provenance (verified/assumed): Verified first-hand by running the attached sandbox; all counts above are its output. Cost is counted in rolls, not timed. The kernel's lockstep claim and the grep-guard against ambient randomness were not exercised.
