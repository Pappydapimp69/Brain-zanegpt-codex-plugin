## E1 — validate vs steward gates disagree in both directions neither is authoritative
- Date: 2026-10-10
- Project: local/gate-differential
- Tags: [governance][verification][testing][harness]
- What: A differential test of the two real intake gates of the memory store, scripts/validate.py (V, in local mode and in the PR-time mode that reuses the steward's regexes) and scripts/steward.py (S, dry run plus one real run), over 60 crafted proposals, 51 real drafts from earlier training passes and a 100-entry sample of promoted canon rebuilt into proposals. On the crafted set in local mode S held 29 that V accepted, V failed 10 that S would promote, both rejected 3, both accepted 15, and 3 carried a forged hold block that both skip. At PR time V closes part of the gap (S-stricter 18) but V-stricter rises to 12. Neither accepted set contains the other.
- Why built: Tension 'which promotion gate is authoritative when the two disagree' names a ZaneGPT gate (3 supporting events, 2 contexts, explicit approval) against Brain's gate (proposal, incoming, steward) and has no stated precedence. Before arguing about precedence across systems, the cheaper question is measurable: do the two gates inside Brain already disagree, in which direction, and what does each catch that the other misses. Supports pole B of tension 'which promotion gate is authoritative when the two disagree' in the narrow reading that nothing cleared elsewhere can be assumed to clear Brain's gates, so a finding re-enters as a proposal and faces every Brain gate; it does not test the ZaneGPT gate itself.
- Design: Stdlib harness; the real scripts are copied into throwaway roots and run as subprocesses, the source store is only read. Verdicts: S is promote, hold or skip (a held block present); V is ok or fail, attributed to the proposal by file name in the error line. Corpus 1 is crafted, one defect per case, each with an expected verdict triple written from reading the code before the run (schema, substance, provenance wording, injection, sandbox, tags, file name, index line, polarity, Composed, dedup, secrets, forged hold block, nine review variants). Hostile and secret-shaped strings are assembled from parts at run time. Corpus 2 is the 51 real drafts; 41 of them already have a promoted twin in the index, so the dedup gate is rerun with that one twin removed. Corpus 3 is every 20th canon entry rebuilt as a proposal with its own index line removed. A consequence test then runs the real steward without the dry flag in an empty-canon root and validates the result. The ZaneGPT gate was read but not run: its thresholds sit in a config file that no script in that repo reads.
- Got right: Pre-registered expectations held on all 60 crafted cases (0 surprises), which shows the code reading was accurate and the counts are not noise. The S-only catches are schema fields (Link, Provenance, ID are required by S only), substance floor, provenance wording, dedup, project parsing, polarity needing Composed, review contents, sandbox overwrite. The V-only catches are tag syntax in the Tags field (4 cases), file name (2), unparseable Composed, an index line without the arrow anchor, secrets in a body or a stored sandbox (2, also under a forged hold block), and injection text in a sandbox file that no proposal names. Where V reuses the steward's own regexes the verdicts match, so injection and provenance wording are one gate seen twice. Output was identical on two runs, and six crafted cases agreed between the throwaway root and the full clone.
- Where/why it failed: Two of six predictions missed, both about corpora and not about the gates. Raw real drafts showed 40 S-holds, all dedup against their own already promoted twin, so the raw count says nothing; with the twin removed the 51 drafts disagree 6 times locally (S-stricter 3, V-stricter 3) and 7 at PR time. The canon sample was S-held only 5 percent, not 30 percent: canon already passed the steward, so it measures rule drift only (4 near-duplicates now caught by dedup, 1 provenance wording, and V-stricter 1 unparseable Composed). Real surprises: 3 real drafts use an ASCII arrow in the index line, S promotes them with a corrupted index line and V fails them; 2 real reviews merely contain the word provenance and fail V at PR time while S applies them (case added after seeing them). Late failure: an uppercase or spaced tag in the index line passes V on the incoming file, S promotes it, and V on the resulting canon fails, steward exits 1 and skips its commit, as does a secret in a body or sandbox.
- Fix: Do not treat either script as the authority. State the effective rule as the conjunction S and V-at-PR-time and V-on-canon, with their private catch sets listed, and close the gaps where both orders are cheap: make V check the index-line tags at incoming time, make S require or normalise the arrow anchor and scan for secrets before it writes canon, and stop V from demanding a provenance field on a review. Until then a proposal needs to clear both.
- Why this fix: The counts show a partial order that has no top: V fails 10 crafted proposals that S promotes, and S holds 29 that V accepts, so replacing either gate by the other loses catches. What decides today is order and side effects, not rank: S is the only one that blocks promotion, V is the only one that can block the commit after canon is already written, which is the worse place to find a defect. Moving the tag and secret checks before the write turns the late failure into an early hold.
- Rule of thumb: Two gates in series with separately written rules have private catch sets, so a pass at one carries no information about the other: in this store 60 crafted cases split 29 / 10 / 3 / 15 (S-stricter / V-stricter / both reject / both accept) and 40 of 51 real drafts looked S-stricter on the raw run only because of dedup against their own promoted twin. For the cross-system tension this means a finding that cleared the outer gate re-enters the inner one as an unverified proposal (double jeopardy), and effective acceptance is the intersection, with the late-failing gate named as the one that can stall everyone. Supports pole B of tension 'which promotion gate is authoritative when the two disagree' for that re-entry reading only.
- Provenance (verified/assumed): Verified first-hand by running the sandbox twice with identical output, by reading both scripts, and by checking six crafted verdicts against the full clone; every count above is computed in the run.
